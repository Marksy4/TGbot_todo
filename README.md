# 📋 Task Bot — личный таск-менеджер в Telegram

Telegram-бот для управления личными задачами: добавление задач по шагам, список активных задач с группировкой по категориям и автоматические напоминания за час до дедлайна.

## Возможности

- ➕ **Добавление задачи** (`/add`) — пошаговый диалог: текст задачи → категория → сложность → дедлайн
- 📋 **Список задач** (`/list`) — все невыполненные задачи, сгруппированные по категориям, с кнопкой «✅ Выполнить»
- ⏰ **Напоминания** — бот сам присылает сообщение, если до дедлайна задачи остался час или меньше
- 💾 Данные хранятся локально в SQLite — никаких внешних сервисов для БД не нужно

## Технический стек

- Python 3.11+
- [aiogram 3.x](https://docs.aiogram.dev/) — асинхронный фреймворк для Telegram-ботов (роутеры, FSM)
- [aiosqlite](https://github.com/omnilib/aiosqlite) — асинхронная работа с SQLite
- [APScheduler](https://apscheduler.readthedocs.io/) — планировщик для проверки дедлайнов
- aiohttp — health-check сервер для хостингов с обязательным HTTP-портом (Render и т.п.)

## Установка и запуск локально

1. **Клонируйте репозиторий и перейдите в папку проекта**

   ```bash
   git clone <ссылка_на_ваш_репозиторий>
   cd task_bot
   ```

2. **Создайте виртуальное окружение** (рекомендуется Python 3.11 или 3.12 — с 3.14 возможны проблемы со сборкой некоторых зависимостей на Windows)

   ```bash
   python -m venv .venv
   # Windows:
   .venv\Scripts\activate
   # Linux/macOS:
   source .venv/bin/activate
   ```

3. **Установите зависимости**

   ```bash
   pip install -r requirements.txt
   ```

4. **Настройте токен бота**

   Скопируйте `.env.example` в `.env` и впишите токен, полученный от [@BotFather](https://t.me/BotFather):

   ```bash
   cp .env.example .env
   ```

   ```
   BOT_TOKEN=ваш_токен_бота
   ```

   ⚠️ Файл `.env` уже добавлен в `.gitignore` — никогда не коммитьте его и не публикуйте токен нигде.

5. **Запустите бота**

   ```bash
   python main.py
   ```

   При первом запуске автоматически создастся файл `tasks.db` со всеми нужными таблицами.

## Запуск 24/7 на своём ноутбуке (Windows)

Бот можно держать постоянно запущенным прямо на ноутбуке — код уже оптимизирован под это (см. раздел «Оптимизации для работы 24/7» ниже). Но нужно донастроить саму Windows, иначе бот остановится при уходе в сон или перезагрузке.

1. **Отключите сон при работе от сети.** Параметры → Система → Питание и батарея → Экран и спящий режим → «Переводить устройство в спящий режим» = **Никогда** (для режима «От сети»). Работа от батареи сон лучше оставить как есть — иначе быстро разрядится, если ноутбук не подключён к сети.
2. **Отключите засыпание при закрытии крышки** (если хотите, чтобы бот работал с закрытой крышкой): Панель управления → Электропитание → «Действия кнопок питания» → «При закрытии крышки» = **Ничего не делать** (только для режима «От сети»).
3. **Запустите бота в фоне без окна консоли** — создайте файл `run_bot.vbs` рядом с `main.py`:

   ```vbscript
   Set WshShell = CreateObject("WScript.Shell")
   WshShell.Run "pythonw.exe main.py", 0, False
   ```

   Двойной клик по `run_bot.vbs` запустит бота без видимого окна. `pythonw.exe` лежит в той же папке, что и `python.exe` (или в `.venv\Scripts\`, если используете виртуальное окружение).

4. **Автозапуск при включении ноутбука** — через Планировщик заданий Windows:
   - `Win + R` → `taskschd.msc`
   - «Создать задачу» → Триггер: «При входе в систему»
   - Действие: «Запуск программы» → выбрать `wscript.exe`, аргументы: `"C:\путь\к\run_bot.vbs"`
   - На вкладке «Параметры» включите «Перезапускать при отказе каждые: 1 минута», попыток — 3-5
   - На вкладке «Условия» снимите галочку «Запускать только при питании от сети», если хотите, чтобы бот работал и от батареи

5. **Проверяйте логи** — все события пишутся в `bot.log` рядом с `main.py` (ротация автоматическая, файл не разрастётся больше ~15 МБ суммарно).

⚠️ Ограничения такого способа: бот перестанет отвечать, если ноутбук выключат, отправят в сон вручную или пропадёт интернет/электричество надолго. Для полной независимости от вашего железа со временем стоит присмотреться к вариантам ниже.

## Деплой в облако (альтернатива ноутбуку)

Если хочется, чтобы бот не зависел от того, включён ли ваш ноутбук, есть несколько вариантов:

- **Render.com** — бесплатный тариф без карты, но с «усыплением» сервиса, которое компенсируется health-check сервером (уже встроен в `main.py`, включается автоматически, если хостинг передаёт переменную `PORT`) и внешним пингом через [UptimeRobot](https://uptimerobot.com/).
- **Oracle Cloud Free Tier** — бессрочно бесплатная VPS, бот разворачивается как systemd-сервис, работает без ограничений.
- **Amvera Cloud** — российский PaaS-хостинг, специализированный на ботах, деплой через `git push`, оплата в рублях, стабильное соединение с Telegram API из России.

## Как это устроено

- **FSM (машина состояний)** — сценарий `/add` реализован через `aiogram.fsm`, каждый шаг диалога — отдельное состояние (`states.py`), данные между шагами хранятся в контексте FSM и попадают в БД только на последнем шаге.
- **Напоминания** — `scheduler.py` каждую минуту опрашивает БД на задачи, у которых дедлайн наступает в течение часа и напоминание ещё не отправлено (поле `reminder_sent` защищает от повторной отправки).
- **База данных** — одна таблица `tasks` (`id`, `user_id`, `title`, `category`, `difficulty`, `deadline`, `status`, `reminder_sent`), вся логика запросов изолирована в `database.py`, хэндлеры о SQL ничего не знают.

## Оптимизации для работы 24/7

Код специально доработан для долгой непрерывной работы (месяцами) на обычном компьютере, а не только для коротких тестовых запусков:

- **Одно постоянное соединение с БД** вместо открытия нового на каждый запрос — меньше нагрузка на диск и процессор при большом количестве обращений за долгое время.
- **WAL-режим SQLite** — устойчивее к внезапному завершению процесса (например, если ноутбук резко выключат), меньше блокировок при одновременном чтении/записи.
- **Индексы** на `(user_id, status)` и `(status, reminder_sent, deadline)` — запросы остаются быстрыми, даже когда накопятся тысячи задач.
- **Логи с ротацией** (`bot.log`, до 5 МБ × 3 файла) — не съедают место на диске за месяцы работы, но история событий сохраняется для отладки.
- **Супервизор с автоперезапуском** — если бот упадёт из-за временной проблемы (обрыв сети, сбой Telegram API), процесс не завершится, а перезапустится сам с нарастающей паузой (5 сек → 5 мин), вместо того чтобы просто "умереть" и требовать ручного вмешательства.
- **Корректное закрытие** соединений с БД и сессии бота при остановке — не оставляет "подвисших" файлов блокировки.

## Безопасность

- Никогда не публикуйте `BOT_TOKEN` в коде, коммитах или переписке. Если токен всё же «засветился» — сразу отзовите его через [@BotFather](https://t.me/BotFather) (`/mybots` → выбрать бота → `Bot Settings` → `Revoke token`) и получите новый.
- Файлы `.env` и `tasks.db` не должны попадать в git — они уже перечислены в `.gitignore`.
